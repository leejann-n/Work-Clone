# WorkClone 팀원 개발 안내

담당 기능을 **정해진 폴더의 새 파일로만** 만들어 PM에게 전달하면, PM이 그대로 넣어서 합칩니다.
기존 파일은 고치지 않습니다. 고쳐야 할 것 같으면 PM에게 먼저 말해 주세요.

| 담당 | 기능 | 백엔드 파일 | 화면 폴더 | API 주소 |
|---|---|---|---|---|
| 팀원 1 | 회의 분석 | `backend/features/meeting.py` | `frontend/features/meeting/` | `/api/meeting/...` |
| 팀원 2 | 회의록 검색 | `backend/features/search.py` | `frontend/features/search/` | `/api/search...` |
| 팀원 3 | 오늘 브리핑 | `backend/features/briefing.py` | `frontend/features/briefing/` | `/api/briefing/...` |
| 팀원 3 | 주간 업무보고 | `backend/features/weekly.py` | `frontend/features/weekly/` | `/api/weekly/...` |
| PM | 업무 메일 | `backend/features/mail.py` | `frontend/features/mail/` | `/api/mail/...` |

각 파일에는 **이미 동작하는 시작점**과 맨 위에 **할 일(TODO) 목록**이 들어 있습니다. 거기서부터 이어서 만들면 됩니다.

---

## 1. 내 컴퓨터에서 실행하기 (로그인·DB·AI 키 없이 됨)

필요한 것: Python 3.11 이상

```bash
cd workclone-platform/backend
pip install -r requirements.txt
uvicorn app:app --reload --port 8000
```

브라우저에서 `http://localhost:8000` 을 열면 **로그인 없이** 바로 들어가집니다.
- 사이드바에서 내 메뉴(예: 회의 분석)를 누르면 내 화면이 뜹니다.
- 데이터는 `backend/data/store/features/*.json` 파일에 저장됩니다. 처음에는 `backend/data/seed/`의 **가짜 회의록 5개·메일 6통**으로 시작합니다.
  처음 상태로 되돌리려면 `backend/data/store/features/` 폴더를 지우면 됩니다.
- AI 키가 없으면 AI 대신 **예시 응답(demo)**이 나옵니다. 화면과 흐름은 이걸로 먼저 만드세요.
  내 OpenAI 키로 직접 시험하고 싶으면 실행 전에 `export OPENAI_API_KEY=...` (Windows: `set OPENAI_API_KEY=...`).
  **키는 절대 코드·채팅·깃헙에 넣지 마세요.**
- 서버 연결 상태 확인: `http://localhost:8000/api/features` → `{"meeting": "ok", ...}`. 오류가 있으면 이유가 나옵니다.
- API 직접 시험: `http://localhost:8000/docs` (FastAPI 자동 문서)

`--reload` 덕분에 파이썬 파일을 저장하면 서버가 자동으로 다시 켜집니다. 화면 파일은 브라우저 새로고침(Ctrl+Shift+R)만 하면 됩니다.

## 2. 백엔드 만들기 — `backend/features/<기능>.py`

파일 안에 `router`만 있으면 서버가 **자동으로 연결**합니다 (`backend/features/__init__.py`).

```python
from features.common import APIRouter, Depends, HTTPException, Ctx, current, db, ask_ai

router = APIRouter(prefix="/api/meeting", tags=["회의 분석"])   # 주소는 꼭 /api/<내 기능>으로 시작

@router.get("/list")
def list_meetings(ctx: Ctx = Depends(current)):          # ctx = 로그인한 직원
    return db.list(ctx, "meetings", order="held_at.desc")
```

### 공통 도구 (`features/common.py`)
| 도구 | 쓰는 법 | 설명 |
|---|---|---|
| `ctx` | `ctx: Ctx = Depends(current)` | 로그인한 직원. `ctx.public()` → 이름·부서·사번·직급. 내 컴퓨터에서는 "로컬 사용자" |
| `db.list` | `db.list(ctx, "meetings", where={"held_at": "2026-11-26"}, order="held_at.desc", limit=50)` | 목록. where는 '같은 값' 조건 |
| `db.get` | `db.get(ctx, "meetings", id)` | 한 건 (없으면 None) |
| `db.insert` | `db.insert(ctx, "meetings", {...})` | 추가. id·만든 사람·부서·만든 시각은 자동 |
| `db.update` | `db.update(ctx, "meetings", id, {"summary": "..."})` | 고치기 |
| `db.delete` | `db.delete(ctx, "meetings", id)` | 지우기 |
| `ask_ai` | `ask_ai(ctx, "meeting_analyze", 시스템지시, 질문, schema=None, demo=예시값)` | AI에게 한 번 묻기. schema(JSON Schema)를 주면 dict로 받음. **1인 하루 50회 한도가 자동으로 세어짐** |
| `recent_runs` | `recent_runs(ctx, 50)` | 자동화 실행 이력 (automation, status, at, run_by_name) |
| `my_automations` | `my_automations(ctx)` | 같은 부서 자동화 목록 |

- 실제 서버(Supabase)에서는 `db`가 **같은 부서 데이터만** 보여 줍니다 (DB 규칙). 내 컴퓨터에서는 모든 데이터가 보입니다.
- `ask_ai`의 `schema`는 모든 속성을 `required`에 넣고 `"additionalProperties": false`로 써야 합니다 (`meeting.py` 예시 참고).
- AI는 비용이 드니 **버튼을 눌렀을 때만** 부르고, 결과는 DB에 저장해서 다시 쓰세요. 화면을 열 때마다 부르면 안 됩니다.
- 사용자에게 보여 줄 오류는 `raise HTTPException(400, "한국어 설명")`.

## 3. 화면 만들기 — `frontend/features/<기능>/`

| 파일 | 내용 |
|---|---|
| `view.html` | 화면 조각 (html·body 태그 없이 내용만) |
| `view.css` | 이 화면 전용 스타일. **반드시 `#page-<기능> ...`으로 시작**해서 다른 화면에 영향이 없게 |
| `view.js` | 동작. 아래처럼 등록 |

```js
(function () {
  var U = window.WCU, api = WCFeature.api;
  WCFeature.register('meeting', {
    init: function (root) { /* 처음 한 번: 버튼 연결 등. root = 내 화면 */ },
    show: function (root) { /* 메뉴를 누를 때마다: 목록 새로고침 등 */ }
  });
})();
```

- `api('/api/meeting/list')` → JSON. `api(주소, {body: {...}})` → POST. 로그인 토큰은 자동으로 붙고, 실패하면 `Error(서버의 한국어 설명)`.
- 글자를 HTML에 넣을 때는 **항상 `U.esc(글자)`** (보안). 숫자 쉼표 `U.fmt(n)`, 마크다운 `U.md(text)`, `U.timeAgo(시간)`.
- 요소는 `root.querySelector(...)`로 찾으세요. `document.getElementById`는 다른 화면과 겹칠 수 있습니다.
- 기본 스타일을 그대로 쓸 수 있습니다: `card`, `btn-primary sm`, `empty`, `fp-grid`(왼쪽 목록 + 오른쪽 상세), `fp-list`, `fp-row`, `fp-error`.
- 아이콘: `<i data-icon="mic" data-size="16"></i>` (쓸 수 있는 이름은 `frontend/js/icons.js`).

## 4. 데이터 표 (`supabase/features.sql`)

**회의록 `meetings`** — 회의 분석이 저장하고, 회의록 검색·오늘 브리핑·주간 업무보고가 읽습니다.
| 열 | 형식 | 설명 |
|---|---|---|
| id, owner_id, department_id, created_at, updated_at | | 자동 |
| title | 글자 | 회의 제목 |
| held_at | 날짜 | 회의 날짜 (`2026-11-26`) |
| participants | 글자 목록 | 참석자 이름 |
| transcript | 글자 | 회의록 원문 |
| summary | 글자 | AI 요약 |
| decisions | 목록 | `["결정 1", "결정 2"]` |
| action_items | 목록 | `[{"task": "할 일", "assignee": "이름", "due": "2026-12-01" 또는 null, "done": false}]` |
| tags | 글자 목록 | 검색용 키워드 |

**메일 `mails`** — 업무 메일(PM)이 관리하고, 오늘 브리핑·주간 업무보고가 읽습니다.
`from_name, from_email, to_name, subject, body, attachments([{name, path}]), received_at, is_read, category, summary, automation_id, run_id, reply_draft, replied_at, sender_id`
(받은 메일: `recipient_id`가 나, 보낸 메일: `sender_id`가 나. 오늘 브리핑은 `GET /api/mail/list?box=inbox`나 `db.list(ctx, "mails", {"recipient_id": ctx.uid})`로 읽으면 됩니다)

**주간 보고 `weekly_reports`** — 주간 업무보고가 씁니다.
`week_start(월요일), content(마크다운), sources, status('초안'|'제출')` · 한 사람당 한 주에 1개

> 표에 **열을 더 넣고 싶으면** 직접 바꾸지 말고 PM에게 말해 주세요. 같은 표를 여러 명이 쓰기 때문에 PM이 `features.sql`에 반영합니다.
> `action_items`의 완료 체크처럼 **다른 사람 데이터를 고치는 기능**은 회의 분석 담당(팀원 1)과 오늘 브리핑 담당(팀원 3)이 API 하나로 정하세요
> (예: 팀원 1이 `POST /api/meeting/{id}/todo`를 만들고, 팀원 3은 그 API를 부름).

## 6. 제출 방법

1. 아래 파일만 압축합니다 (다른 파일은 넣지 않기).
   ```
   backend/features/<기능>.py
   frontend/features/<기능>/view.html, view.css, view.js
   (필요하면) backend/data/seed/<표>.json 에 추가한 가짜 데이터
   ```
2. **한 장짜리 설명**을 같이 보냅니다.
   - 만든 API 목록 (주소 · 하는 일)
   - 추가로 필요한 표·열 (있으면)
   - 시험 방법 (어떤 순서로 누르면 무엇이 나오는지)
   - 아직 안 된 것
3. 보내기 전에 확인: 서버 시작 시 오류 없음 · `/api/features`에서 내 기능이 `"ok"` · 브라우저 콘솔(F12)에 빨간 오류 없음.
